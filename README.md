## 现象

典型特征（**四条同时出现，基本就是这个病**）：

| 检查项 | 表现 |
| --- | --- |
| 桌面上的 `.lnk` | 全部白纸 + 蓝色快捷箭头 |
| 桌面上的 docx / pdf / 文件夹 / 图片 | 图标正常 |
| 同一个 `.lnk` 复制到文档、下载、`%TEMP%` | 图标立刻正常 |
| 新建一个干净的 `.lnk` 放桌面 | 依然白纸 |

换句话说：**问题严格绑定在「文件位于桌面 + 文件类型是 .lnk」这一个组合上**，文件内容本身没坏。

真实测出来的数字长这样（`SHGetFileInfo` 取图标后数彩色像素）：

```
桌面 Photoshop.lnk              彩色像素 54   ← 白纸（只有中间那个蓝箭头是彩的）
%TEMP%\zz_ps_new.lnk            彩色像素 692  ← 同一个字节的文件，换个目录就正常
Documents\Photoshop.lnk         彩色像素 692  ← 正常
```

## 30 秒判断自己是不是这个问题

不用装任何东西，三步：

1. 看桌面的快捷方式：**蓝色小箭头还在吗？** 在 → 继续下一步；不在但图标也白 → 见[症状变体](#症状变体与对应处置)的 C。
2. 把桌面上任意一个白纸快捷方式，**复制粘贴到「文档」文件夹**。
3. 回桌面按 `F5` 刷新，再看那个副本的图标。

- 副本在「文档」里**变成彩色** → 就是这个病，用本仓库修。
- 副本在「文档」里**还是白纸** → 是这个快捷方式文件本身坏了（目标程序被卸载 / 路径失效 / 图标资源没了），不是桌面问题，见[修完还剩个别白纸图标怎么办](#修完还剩个别白纸图标怎么办)。

## 通用版：先自检，能修的自动修（推荐）

本仓库的主脚本是 `Repair-AllIcons.ps1`。它**不是只针对「桌面」这一个病因，也不是只针对作者机器上那十几个软件**：它对每一个 `.lnk` 单独判断，再按判定只做对应的动作。

### 怎么判断的（不看彩色像素，看相似度）

旧脚本的做法是数「彩色像素」，少于 80 就当白纸——这会误报，因为很多程序图标本身是黑白或深色的。实测作者这台机器上 4 个被旧脚本判成「白纸」的快捷方式，目标程序 exe 自身的图标彩色像素只有 **24 / 0 / 0**，它们其实一直是好的。

新脚本做三张图的对比：

| 参照/对象 | 怎么来的 | 含义 |
| --- | --- | --- |
| 兜底图 A | 临时造一个指向不存在文件的 `.lnk`，取它的图标 | 就是「白纸 + 蓝箭头」的样子 |
| 目标图 B | 直接对 `.lnk` 指向的 exe 取图标 | 正常情况下应该显示的样子 |
| 当前图 | 该 `.lnk` 在它所在文件夹里实际显示的图标 | 待判断的对象 |

三张图统一缩到 32×32，逐像素算平均绝对差（阈值 12，小于即视为同一张图）：

- 当前图**不像**兜底图 → 显示的是真图标，**正常**（哪怕是黑白、深色图标）
- 当前图像兜底图 → 再把同一个 `.lnk` **复制到临时目录**取图做对照
  - 临时目录里正常 → **桌面通道坏了**
  - 临时目录里也白纸 → 再看：目标程序在不在、exe 自己有没有图标资源

### 会给出这 5 种判定

| 判定 | 具体情况 | 工具动作 |
| --- | --- | --- |
| `正常` | 当前图不像兜底图 | 不动它 |
| `可修(桌面)` | 文件夹里白纸、复制到别处就正常 | 清注册表空白图标位 → 重建图标缓存 → 迁移桌面路径（仅扫桌面时） |
| `可修(单)` | 复制到别处还是白纸，但目标程序图标正常 | 重写该 `.lnk` 的图标位置为 `<目标程序>,0` |
| `可修(路径)` | 目标程序搬家了（原路径失效） | 按 exe 文件名在 App Paths / 已安装程序清单 / Program Files 里找回，改写目标路径 + 工作目录 + 图标 |
| `需人工` | 商店应用（没有目标路径）、程序已卸载且找不到、exe 本身没有图标资源、找到多个同名程序 | 只输出原因和下一步怎么做，不硬改 |

`可修(路径)` 是通用性最关键的一块：程序从 `D:\旧目录` 挪到别处、或者装在移动硬盘上换了盘符，图标就会变白纸——这种以前只能手动重建快捷方式，现在能自动找回。

### 实测输出长这样

```
  扫描目录 : C:\Users\你\Desktop

  快捷方式                                     判定           原因
  ------------------------------------------------------------------------------------------------
  A_目标缺失.lnk                               需人工          目标程序不存在（已卸载或路径变了）
  B_正常.lnk                                 正常           显示的是程序自己的图标
  D_索引越界.lnk                               可修(单)        快捷方式图标解析坏了（可重写图标位置）
  F_目标搬家.lnk                               可修(路径)       程序搬家了，已在别处找到同名程序
  ------------------------------------------------------------------------------------------------

  汇总：正常 2   桌面通道可修 0   单个 lnk 可修 1   路径可修 1   需人工 1   可疑 0
```

修复完会自动**复检一遍**，把仍修不了的单独列出来，并给出手动处理办法。

### 修不了的，它不会假装能修

工具的能力边界就是上面「需人工」那四类，这里说明白，避免期待落空：

- **商店应用 / UWP 快捷方式**（没有目标路径）：图标由应用包自己提供，改不了，重装应用或从开始菜单重新拖出来。
- **程序真的卸载了**：系统里找不到同名 exe，没法凭空造图标——删掉快捷方式，重装后再拖。
- **exe 文件本身没有图标资源**：某些绿色软件/驱动工具就是没有图标，只能用「右键 → 属性 → 更改图标」手动指定一个 `.ico`。
- **找到多个同名程序**：宁可不动，也不替你猜。

### 备份与回滚

每次修复前都会在 `%TEMP%\IconRepair_<时间戳>\` 建一个备份目录：

- 注册表：`UserShellFolders.reg`、`ShellFolders.reg`、`ShellIcons_*.reg`、`lnkfile.reg`、`CLSID_lnk.reg`
- 被改动的快捷方式：`lnk\` 子目录里有原文件，`lnk\_map.txt` 记录「文件名 → 原始完整路径」

`一键回滚.bat`（或 `-Restore`）会读最近一次的备份目录，逐项还原快捷方式、注册表和桌面路径。

> 说明：机器级注册表项（`HKLM\SOFTWARE\Classes\lnkfile`）的还原需要管理员权限；普通权限下这些项通常会提示「导入失败」，属正常，不影响 HKCU 部分和快捷方式的还原。

## 手把手教程（双击即用）

全程不需要管理员权限、不需要装任何软件、不需要碰命令行。

### 第 0 步：下载

1. 打开 https://github.com/wwj5/desktop-icon-repair
2. 点页面右上绿色 **Code** 按钮 → **Download ZIP**
3. 把下载到的 zip **解压**到任意文件夹（例如 `D:\桌面图标修复\`）
4. 解压后文件夹里应该有这些文件（`.gitattributes` 是隐藏文件，看不到不影响）：

```
一键诊断.bat
一键修复.bat
一键回滚.bat
Repair-AllIcons.ps1      ← 主脚本，上面三个 bat 都调它
Diagnose-DesktopIcons.ps1 ← 旧诊断入口（只转发到主脚本）
Fix-DesktopIcons.ps1      ← 旧版「只换桌面路径」脚本
README.md
LICENSE
```

> ⚠️ **三个 bat 必须和 ps1 放在同一个文件夹里**，不要把 bat 单独拖到桌面。bat 是靠「自己所在目录」去找 ps1 的。

### 第 1 步：双击 `一键诊断.bat`（只读，绝对安全）

会发生什么：

1. 弹出一个黑色命令窗口，标题是「桌面快捷方式图标诊断（只读）」。
2. 窗口里先打印你的桌面路径，再逐行列出每个快捷方式：**名称 / 判定 / 原因**。
3. 跑到最后有一行汇总，然后停住等你按任意键。

判定只有 5 种，逐个解释：

| 判定 | 意思 | 要不要修 |
| --- | --- | --- |
| `正常` | 显示的是程序自己的图标（黑白图标也算正常） | 不用 |
| `可修(桌面)` | 桌面上白纸，复制到别处就正常 | 要，进第 3 步 |
| `可修(单)` | 这个快捷方式的图标位置坏了 | 要，进第 3 步 |
| `可修(路径)` | 程序搬家了，原路径失效 | 要，进第 3 步 |
| `需人工` | 商店应用 / 程序已卸载 / exe 本身没图标 / 同名程序有多个 | 修不了，脚本会告诉你怎么办 |

汇总行长这样：

```
  汇总：正常 23   桌面通道可修 4   单个 lnk 可修 0   路径可修 1   需人工 1   可疑 0
```

- **四个"可修"全是 0** → 你的图标是好的，不用修复，直接看[症状变体](#症状变体与对应处置)找别的原因。
- **桌面通道可修 有值（比如 27 个全是）** → 就是本文这个病，继续第 2 步。
- **只有"单个 lnk 可修"或"路径可修"有值** → 也是第 3 步，工具会就地修那几个，不会动桌面路径。
- **只剩"需人工"** → 那几个本来就修不了，看第 3 步跑完后的手动提示。

诊断脚本还会顺手做一次**对照测试**：把一个白纸快捷方式复制到临时目录再取图，用来区分「桌面通道坏」和「快捷方式自己坏」——结论就写在判定那一列里。

### 第 2 步：保存你手上的活

修复过程会**重启资源管理器**（任务栏和桌面会闪一下、图标重新排一遍）。所以先：

- 保存 Word / Excel / CAD / 绘图软件里没存的文件
- 关掉正在复制大文件的窗口

不需要重启电脑，不需要注销。

### 第 3 步：双击 `一键修复.bat`

会发生什么：

1. 窗口标题「桌面快捷方式图标修复」，先列出它要做什么。
2. 提示 `确认开始修复？输入 y 再回车（输入其它任意键取消）:` —— **输入字母 `y` 然后回车**。
3. 脚本开始跑，屏幕上的顺序大致是这样（以桌面通道坏为例）：

```
==> 建立参照图（兜底白纸图标）
    OK   已取到兜底图标参照（32×32）

==> 检测桌面快捷方式
  快捷方式                        判定            原因
  Adobe Photoshop 2025.lnk       可修(桌面)      桌面图标通道坏了（复制到别处就正常）
  ...
  汇总：正常 0   桌面通道可修 27   单个 lnk 可修 0   路径可修 0   需人工 0   可疑 0

==> 准备修复
    OK   将针对 27 个异常项执行修复；正常项不动

==> 备份
    OK   备份目录：C:\Users\你\AppData\Local\Temp\IconRepair_20261109_133113

==> 1) 清理快捷方式图标注册表
    OK   移除 ...\Shell Icons 的 29（原指向 [C:\WINDOWS\Blank.ico]，无有效图标）
    OK   重设 lnkfile\shellex\IconHandler（原值 []，写入 machine 级）

==> 2) 重建图标缓存
    OK   图标缓存已清理（原来 12 个 / 512 KB，删除 12 个、失败 0 个）

==> 重启资源管理器让前面的改动生效
    OK   已重启

==> 3) 修复快捷方式本身
    OK   无需处理（没有单个 lnk 异常）

==> 4) 桌面通道修复：迁移桌面路径
    OK   源：48 项 / 106.92 MB
    OK   副本核对通过：48 项 / 106.92 MB
    OK   桌面已指向 C:\Users\你\DesktopNew2

==> 复检
  修复后：正常 27   仍异常 0   需人工 0
```

4. 最后打印「完成。」并列出**本次改了什么**（注册表 / 图标缓存 / 快捷方式 / 桌面路径）和备份目录，停住等你按键。

> 只有出现 `可修(桌面)` 时，才会走「重建缓存 + 迁移桌面路径」这两步；只是个别快捷方式坏了，就只改那几个 lnk，桌面路径一个字节都不动。

### 第 4 步：看桌面

资源管理器重启后，桌面上应该全部恢复彩色。可以再跑一次 `一键诊断.bat` 复核：

```
  汇总：正常 27   桌面通道可修 0   单个 lnk 可修 0   路径可修 0   需人工 0   可疑 0
```

四个"可修"全归零，就说明清干净了。

### 第 5 步：确认没问题后，处理旧桌面文件夹

修复后系统桌面是 `C:\Users\你\DesktopNew2`（可自定义），但**显示名称仍然是「桌面」**，所有软件「保存到桌面」也会自动跟过去。

旧的 `C:\Users\你\Desktop` 还在原位（一个文件都没动），可以：

- **先留几天**，确认新桌面一切正常、没有丢东西；
- 再决定要不要删。删之前建议并排放着两个文件夹对比一眼。

> 旧桌面上快捷方式仍然显示白纸——它现在只是个普通文件夹，却还带着「曾经是桌面」的残留标记，不影响使用。

### 如果中途出问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 双击 bat 一闪就没了 | 杀软/系统策略拦了 bat | 右键 bat →「以管理员身份运行」；或改成手动跑 ps1（见[命令行](#脚本用法命令行)） |
| 提示「不是内部或外部命令」 | 系统 PATH 被精简过 | 本仓库的 bat 已用绝对路径调用 PowerShell；若仍报错，直接手动跑 ps1 |
| 提示「禁止运行脚本」 | PowerShell 执行策略限制 | bat 里已经带了 `-ExecutionPolicy Bypass`，一般不会出现；手动跑时也带上这个参数 |
| 第 2/6 步卡住或报项数少于源 | 有文件被程序占用 | 关掉占用的程序（通常是资源管理器缩略图、WPS、CAD），再重跑 |
| 第 4/6 步报备份失败 | `reg.exe` 被拦或磁盘满 | 脚本会**中止且不改任何注册表**，清理后重跑 |
| 第 6/6 步后图标还是白纸 | 不是本文这个问题 | 跑 `sfc /scannow` 和 `DISM /Online /Cleanup-Image /RestoreHealth`，见[注意事项](#注意事项) |
| 修完想退回原样 | —— | 双击 `一键回滚.bat` |

## 真实案例（本文档的来源）

时间线，全部为实测记录：

1. **起因**：装了一个「去 Windows 桌面快捷方式箭头」的小工具，把快捷方式的蓝色小箭头去掉了。用完就走了，没管它改了什么。
2. **发作**：之后某次开机，桌面上二十多个 `.lnk` 全部变成「白纸 + 蓝色快捷箭头」，而桌面的 docx、pdf、文件夹、图片图标全部正常。
3. **误以为是图标缓存**：清了 `iconcache_*.db`、注销重登、重启、跑 `sfc /scannow` 与 `DISM`，全部无效。
4. **误以为是快捷方式坏了**：把桌面某个 lnk 复制到 `%TEMP%`，图标立刻正常；再新建一个指向 `notepad.exe` 的干净 lnk 放桌面，依然是白纸。→ 文件没问题，是「桌面这个位置」的问题。
5. **查箭头工具的残留**：发现 `HKCU/HKLM` 的 `Explorer\Shell Icons` 下，值 `29` 和 `77` 都被指向 `C:\Windows\Blank.ico`（一个空白图标文件）。删掉这两个值后，**蓝色快捷箭头回来了**，但白纸问题**仍然存在**。
6. **逐项排除**：`lnkfile` 注册表全树正常、`IconHandler` 的 CLSID 指向 `windows.storage.dll`、两个 dll 签名 `Valid`、`Approved/Blocked` 列表无异常、`FolderDescriptions` 正常、桌面路径注册表值也正常——全都查不出问题。
7. **最终修好**：把桌面内容整体复制到 `DesktopNew`，把系统桌面位置指过去，重启资源管理器。**桌面上的 lnk 全部恢复彩色图标**（Photoshop = 692、豆包 = 680、抖音 = 232），同时 32px 图标缓存从空壳（24 字节）自动长回 1 MB。
8. **残留**：修完后仍有 4 个快捷方式保持白纸（ChatGPT 54、DeepSeek Harness 75、Mineradio 53、剪映专业版 53），把这 4 个文件复制到临时目录取图**同样是 54** —— 说明它们是**文件本身**的图标失效（目标程序卸了 / 路径变了 / 图标资源没了），属于另一类问题，见[修完还剩个别白纸图标怎么办](#修完还剩个别白纸图标怎么办)。

结论：**箭头工具改的是「图标配置」，但它留下的副作用是「桌面命名空间的 lnk 图标解析链路整条失效」。配置能改回来，链路不能——只能换路径让系统重建。**

## 根因

Windows 不是把桌面当普通文件夹，而是当成一个**虚拟容器**（桌面命名空间，`FOLDERID_Desktop`）。这个容器负责两件事：列出桌面上的所有项、给每一项配图标。

它配图标时走两条完全不同的路：

```
桌面命名空间（虚拟容器）
        │
        ├── 普通文件（docx / pdf / exe / 文件夹）
        │       └── 转交文件系统 → 读「文件关联」里的默认图标  ✅ 一直正常
        │
        └── 快捷方式（.lnk）
                └── 必须调用「图标处理器」IconHandler
                        CLSID {00021401-0000-0000-C000-000000000046}
                        实现于 C:\Windows\System32\windows.storage.dll
                        → 解析 .lnk 的目标程序 → 抽取目标程序图标
                        ❌ 这一步失败 → 退回兜底图标：白纸 + 蓝箭头
```

**坏的不是图标文件、不是注册表项、不是缓存，而是「桌面命名空间」和桌面路径（`C:\Users\<user>\Desktop`）之间的绑定关系。** 绑定一旦坏掉，容器每次去调图标处理器都失败，只能发兜底图标。

这也解释了为什么「注销重登」没用：注销只是重建进程，进程起来读的还是同一条坏绑定。

> 桌面上只有 `.lnk` 走 IconHandler，docx / pdf / 文件夹走的是「文件关联」另一条路。所以才会出现「桌面上什么都正常，就快捷方式全白纸」这种看起来自相矛盾的现象——它恰恰证明坏的是 lnk 那条链路，而不是整个桌面。

## 典型诱因：去快捷方式箭头工具到底做了什么

网上的「去箭头」工具（绿色小软件、reg 脚本、批处理、"一键美化"包）做的其实不是一件事，常见有下面 5 种手法。**前 2 种只是改配置，能改回来；后 3 种会留下本问题需要的「绑定损坏」。**

| # | 常见手法 | 具体位置 | 副作用 | 能否还原 |
| --- | --- | --- | --- | --- |
| 1 | 把「快捷方式覆盖图标」指向一个空白 ico | `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Icons` 的 `29`、`77` → `Blank.ico` | 箭头消失；若空白 ico 是 0 字节 / 尺寸不全 / 索引不存在，部分视图下会直接退成白纸 | ✅ 删掉两个值即可 |
| 2 | 删除 `IsShortcut` 值 | `HKEY_CLASSES_ROOT\lnkfile` 的 `IsShortcut` | Win7 时代有效，Win10/11 基本无效，但很多工具还在沿用；单独做这一步不会造成白纸 | ✅ 一般不需要还原 |
| 3 | 改写 `lnkfile\DefaultIcon` | `HKCR\lnkfile\DefaultIcon` → 某个 ico 或 `shell32.dll,-N` | 默认图标被换掉；索引写错就变成白纸 | ⚠️ 可改回来，但可能已被其它组件覆盖 |
| 4 | 劫持 `lnkfile\shellex\IconHandler` | `HKCR\lnkfile\shellex\IconHandler` 默认值、`CLSID\{00021401-…}` 的 `InProcServer32` | 本来该指向 `windows.storage.dll`，被改成一个不存在的 dll / 空 GUID / 第三方 dll，**图标处理器整条链路断掉** | ⚠️ 值能改回来，桌面命名空间已缓存的坏绑定**不会自动恢复** |
| 5 | 直接替换 / patch `shell32.dll` 里的图标资源，或用第三方 shell 扩展接管 | `C:\Windows\System32\shell32.dll`、`Approved` / `Blocked` 列表、桌面命名空间里的第三方扩展项 | 系统文件签名失效或被替换；shell 扩展在桌面容器上挂掉，桌面给 lnk 配图标时异常 | ❌ 需要 `sfc /scannow` 或卸载工具，代价最大 |

本文案例同时命中 **1 和 4 附近**：`Shell Icons` 的 29/77 确实被指向 `C:\Windows\Blank.ico`（删掉后箭头恢复），但桌面 lnk 依旧白纸，说明箭头工具还动过别处、在桌面命名空间里留下了失效的外壳绑定。

**所以「把箭头工具改过的地方全部手动改回来」这条路，实测同样救不回来**——你能改的是注册表值，改不了容器里那条已经烂掉的绑定。

## 症状变体与对应处置

同样是「箭头工具惹的祸」，实际表现有 4 种，处置方式完全不同：

| 症状 | 具体表现 | 大概率原因 | 怎么办 |
| --- | --- | --- | --- |
| A. 箭头还在，图标全白纸 | 桌面全部 lnk 是「白纸 + 蓝箭头」，换目录正常 | 桌面命名空间绑定损坏（**本文**） | 双击 `一键修复.bat` |
| B. 箭头没了，图标正常 | 快捷方式和普通程序一样，没有小箭头 | `Shell Icons 29/77` 指向空白 ico | 删掉这两个值，或删掉整个 `Shell Icons` 键 |
| C. 箭头没了，图标也变白纸 | 两个症状同时出现 | 29/77 的空白 ico 本身异常 + 桌面绑定损坏 | 先删 29/77，再双击 `一键修复.bat` |
| D. 只有部分图标异常 | 其它正常，个别白纸 | 该快捷方式本身坏了（目标程序卸了 / 路径变了） | 重建那一个快捷方式，见下一节 |

判断入口很简单：**先看箭头在不在，再做一个「复制到文档」的对照**。

## 为什么常规方法都没用

以下这些是网上流传的常见招数，对**本问题全部无效**（已逐项实测排除）：

- 清空并重建图标缓存（`iconcache_*.db`）
- 改 `Shell Icons` 覆盖位（值 `29` / `77`），或指向别的 ico
- 改 `lnkfile\DefaultIcon`
- 改 `lnkfile\shellex\IconHandler` 的 CLSID
- 重建 / 删除 `desktop.ini`
- 删除 `Bags\1\Desktop` 视图缓存
- 改文件夹 `ReadOnly` / `System` 属性、`Hidden`
- 改 `HKCU\Software\Classes` 下的 `.lnk` / `CLSID\{00021401-…}` 覆盖
- 改 `FolderDescriptions` 里桌面的 `Icon` / `LocalizedName`
- 删除桌面命名空间里的第三方扩展项（如云盘）
- 检查 `Shell Extensions\Blocked` / `Approved` 列表
- 给 `.lnk` 显式写死 `IconLocation`
- 注销并重新登录
- **把去箭头工具改过的注册表项全部手动还原**（本文案例实测同样无效）
- 重装图标包 / 重装某个程序

**能全部排除，是因为它们的共同前提是「配置项写错了」；而本问题的原因是「路径绑定坏了」，换个路径才能重建。**

另外注意：`Bags\1\Desktop` 是**桌面图标位置**的视图缓存，**不要**为了修图标去删它——删了图标能回来，但你摆好的图标坐标会全部丢失（本文作者就踩过这个坑）。

## 自查：我是不是被箭头工具改过

全部只读，不改任何东西。用普通权限的 PowerShell 跑即可：

```powershell
# 1. 箭头覆盖位：有没有被指向空白图标（有输出 = 被改过）
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Icons" 2>$null
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Shell Icons" 2>$null
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Explorer\Shell Icons" 2>$null

# 2. 快捷方式图标的处理器链路是否完整（下面每一条都应该有正常的默认值）
reg query "HKCR\lnkfile" /v DefaultIcon
reg query "HKCR\lnkfile\shellex\IconHandler"
reg query "HKCR\CLSID\{00021401-0000-0000-C000-000000000046}\InProcServer32"

# 3. 系统文件有没有被替换（签名必须是 Valid）
Get-AuthenticodeSignature C:\Windows\System32\windows.storage.dll | Select-Object Status
Get-AuthenticodeSignature C:\Windows\System32\shell32.dll | Select-Object Status

# 4. shell 扩展有没有被屏蔽（列表里不应出现 00021401 / 00021400）
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Shell Extensions\Blocked" 2>$null
```

正常应该长这样（对照用）：

| 项 | 正常值 |
| --- | --- |
| `HKCR\lnkfile\DefaultIcon` | `%SystemRoot%\system32\shell32.dll,3` |
| `HKCR\lnkfile\shellex\IconHandler` | `{00021401-0000-0000-C000-000000000046}` |
| `CLSID\{00021401-…}\InProcServer32` | `C:\Windows\System32\windows.storage.dll`（`ThreadingModel=Both`） |
| 两个 dll 的签名 | `Valid`（`CN=Microsoft Windows`） |
| `Shell Icons` 的 `29` / `77` | **不存在**，或指向一个真实存在的彩色 ico |
| `Shell Extensions\Blocked` | 不存在，或不含 `{00021401}` / `{00021400}` |

**如果上面全部正常，但桌面 lnk 依旧是白纸 —— 那就是本文这一种，可以放心用本仓库的脚本。**

> 判据补充：主脚本 `Repair-AllIcons.ps1` 用的是**相似度比对**（兜底图 / 目标程序图 / 当前图，32×32 平均绝对差 < 12 视为同一张），不再用「彩色像素 < 80」这类阈值——后者会把黑白图标误判成白纸。
> ⚠️ 不要用 `Icon.ExtractAssociatedIcon` 判断：它对 `.lnk` 一律返回同一个默认图标，是假信号。

## 修复原理（脚本内部做了什么）

主脚本按检测结果决定动作，四类判定对应四套动作，**没检测到的问题不碰**：

| 判定 | 动作 |
| --- | --- |
| `正常` | 什么都不做 |
| `可修(桌面)` | ① 清注册表空白图标位 → ② 重建图标缓存 → ③ 迁移桌面路径 → ④ 重启资源管理器 |
| `可修(单)` | 备份该 lnk → 重写 `IconLocation` 为 `<目标程序>,0` → 复检 |
| `可修(路径)` | 备份该 lnk → 找回同名 exe → 改写 `TargetPath` / `WorkingDirectory` / `IconLocation` → 复检 |
| `需人工` | 只输出原因与手动处理建议，不硬改 |

其中「桌面通道」这一类，原理是**不修那条坏绑定，而是换一条干净的路径，让系统重建它**：

```
① 把桌面全部内容完整复制到新文件夹（原桌面一个文件都不动）
                ↓
② 把系统「桌面」位置改指向新文件夹
   HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders\Desktop
   HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Folders\Desktop
                ↓
③ 重启资源管理器 → 系统用新路径重新初始化桌面命名空间
                ↓
④ 图标处理器调用恢复 → 快捷方式图标变回彩色
   同时 32px 图标缓存会从空壳（约 24 字节）恢复成正常档（约 1 MB）
```

旧版 `Fix-DesktopIcons.ps1` 仍按 6 步执行（新引擎把等价动作并进了上面的判定表），每一步都能中止、都能回滚：

| 步骤 | 做什么 | 出问题会怎样 |
| --- | --- | --- |
| 1/6 | 统计桌面项数与总大小，作为基线 | 只读，不会失败 |
| 2/6 | `robocopy /E /COPY:DAT` 完整复制（保留时间戳） | 退出码 ≥8 立即中止，**不改注册表** |
| 3/6 | 逐项核对副本与源的数量、大小 | 数量少于源（文件被占用）→ 中止，**不改注册表** |
| 4/6 | `reg export` 备份两个注册表键，并校验文件真实落盘 | 备份文件不存在或过小 → 中止，**不改注册表** |
| 5/6 | 改两个 `Desktop` 值，并给新文件夹加 `ReadOnly`（让 `desktop.ini` 的显示名「桌面」生效） | —— |
| 6/6 | 重启资源管理器，重新取图标复核 | 资源管理器没自动起来 → 提示手动启动 |

修复后桌面路径变了（例如 `C:\Users\<user>\DesktopNew`），**功能完全一样，显示名仍然是「桌面」**，所有「保存到桌面」的软件都会自动跟随。

## 脚本用法（命令行）

主脚本是 `Repair-AllIcons.ps1`。三个 bat 只是它的便捷入口。

```powershell
# 1. 只检测（只读，不改任何东西）
powershell -ExecutionPolicy Bypass -File .\Repair-AllIcons.ps1 -DiagnoseOnly

# 2. 检测 + 修能修的（会先问一次，Ctrl+C 或等 5 秒内可取消）
powershell -ExecutionPolicy Bypass -File .\Repair-AllIcons.ps1

# 3. 不给确认提示（bat 里用的就是这种）
powershell -ExecutionPolicy Bypass -File .\Repair-AllIcons.ps1 -Yes

# 4. 只看某个文件夹（自测用；指定后不会做桌面路径迁移）
powershell -ExecutionPolicy Bypass -File .\Repair-AllIcons.ps1 -DiagnoseOnly -ScanPath "D:\SomeFolder"

# 5. 桌面通道要迁移时，指定新桌面位置（默认 %USERPROFILE%\DesktopNew2）
powershell -ExecutionPolicy Bypass -File .\Repair-AllIcons.ps1 -NewDesktopPath "D:\Desktop"

# 6. 回滚到最近一次备份
powershell -ExecutionPolicy Bypass -File .\Repair-AllIcons.ps1 -Restore
```

| 参数 | 含义 |
| --- | --- |
| `-DiagnoseOnly` | 只检测不修 |
| `-Yes` | 跳过 5 秒确认（bat 用） |
| `-ScanPath <路径>` | 只扫指定文件夹，且不触发桌面路径迁移 |
| `-NewDesktopPath <路径>` | 迁移桌面时的新位置 |
| `-Restore` | 回滚最近一次备份 |

### 旧的两个脚本

| 文件 | 状态 | 说明 |
| --- | --- | --- |
| `Diagnose-DesktopIcons.ps1` | 仅作转发 | 旧版自带「彩色像素 < 80」阈值判据会误报，现在只转发到新引擎的 `-DiagnoseOnly`，保留老命令习惯 |
| `Fix-DesktopIcons.ps1` | 保留 | 只做「桌面路径迁移 + 回滚」这一件事，新引擎已包含同功能；老用户脚本无需改 |

> 为什么弃用彩色像素阈值：`-WhiteMax 80 / -NormalMin 200` 这套判据在黑白图标、深色图标、低对比度图标上必然误报（实测同一台机器上 4 个正常快捷方式被判成白纸）。相似度比对不依赖颜色饱和度，所以不会犯这个错。

## 修完还剩个别白纸图标怎么办

修复后如果还有三四个快捷方式是白纸，**先做对照**：把那个 lnk 复制到「文档」再取图。

- 副本在「文档」里**也是白纸** → 是这个快捷方式文件本身坏了（跟桌面无关）。常见原因与处理：

| 原因 | 怎么确认 | 处理 |
| --- | --- | --- |
| 目标程序已卸载 / 被移动 | 右键 lnk →「属性」→「目标」路径不存在 | 删掉这个 lnk，重装程序后重新创建 |
| 程序是绿色版 / 便携版，exe 换了位置 | 同上 | 重指向新的 exe |
| 程序本身没有带图标资源（.exe 里没有 icon） | 直接双击 exe 看它自己的图标 | 属正常现象，可以手动给 lnk 指定一个 ico |
| lnk 被第三方"美化"工具改过 `IconLocation` | 属性里的「更改图标」指向一个不存在的文件 | 点「更改图标」重选，或直接重建 lnk |

- 副本在「文档」里**是彩色** → 桌面绑定还没修干净，重跑一次 `一键修复.bat`；仍不行就换一个全新的路径：`-NewDesktopPath "D:\Desktop2026"`。

> 这一节里「目标程序已卸载 / 被移动」「lnk 被改过 `IconLocation`」这两类，新版脚本已经能自动处理（判定 `可修(路径)` / `可修(单)`）；剩下的「程序本身没图标」仍需要手动指定 ico。

重建单个快捷方式的最快办法：删掉旧的 lnk，从开始菜单把程序图标拖到桌面（或右键 exe →「发送到」→「桌面快捷方式」）。

## 回滚

```powershell
powershell -ExecutionPolicy Bypass -File .\Repair-AllIcons.ps1 -Restore
```

或者双击 `一键回滚.bat`。旧版 `Fix-DesktopIcons.ps1 -Restore` 仍然可用（只回滚桌面路径）。

会读 `%TEMP%\IconRepair_<最近一次时间戳>\` 备份目录，**逐项还原**：

- 被改过的快捷方式（`lnk\` 子目录 + `lnk\_map.txt` 里记录的原路径）
- 注册表（`User Shell Folders` / `Shell Folders` / `Shell Icons` / `lnkfile` / `CLSID`）
- 桌面路径（`manifest.json` 里记录的修复前值）

原桌面文件夹**全程没有被改动**，所以回滚后和修复前完全一样。

> 机器级注册表项（`HKLM\SOFTWARE\Classes\lnkfile` 等）的导入需要管理员权限；普通权限下会提示「导入失败」，这不影响当前用户设置与快捷方式的还原。

## 常见问题 FAQ

**Q：会丢文件吗？**
不会。脚本只做复制 + 改一个注册表路径，从不删除或移动任何文件。复制前后还会核对项数和总大小，对不上就中止。

**Q：需要管理员权限吗？**
不需要，也不会弹 UAC。用户级设置全在 `HKCU` 下；个别机器级键（`HKLM\Software\Classes\lnkfile`）写不进去时，脚本会自动改写当前用户的覆盖项 `HKCU\Software\Classes\lnkfile`，效果一样、权限够用。

**Q：会不会把好的图标改坏？**
不会。工具先自检再动手：判定为 `正常` 的一律不碰；只有确认「显示了兜底白纸图」的才修，而且每个 lnk 改动前都单独备份。

**Q：桌面在 OneDrive 里怎么办？**
先确认你的桌面是不是被 OneDrive 接管（右键桌面 → 属性看位置是否在 `OneDrive\桌面`）。如果是，换到 `DesktopNew` 后，新桌面**不再同步到 OneDrive**。这类情况建议直接把 `-NewDesktopPath` 指定成 OneDrive 下的另一个文件夹，例如：
```powershell
powershell -ExecutionPolicy Bypass -File .\Fix-DesktopIcons.ps1 -NewDesktopPath "$env:USERPROFILE\OneDrive\Desktop2"
```

**Q：修复后原来的桌面文件夹能删吗？**
可以，但要**先确认几天没问题**。删之前建议并排打开两个文件夹比一眼，确认没有「新桌面里没有的东西」。

**Q：修复后图标位置全乱了？**
会重新排一遍（因为换了文件夹）。想保住原坐标，可以在修复前先给桌面截图。**不要**为了保坐标去删 `Bags\1\Desktop` —— 那正是存坐标的地方。

**Q：为什么注销重登没用？**
注销只是重启进程，进程起来读的还是同一条坏掉的绑定。换路径才会触发重建。

**Q：这个修复会不会影响「保存到桌面」？**
不会。系统桌面位置换了，所有软件调用「桌面」这个已知文件夹时都会拿到新路径，显示名仍是「桌面」。

**Q：以后怎么避免再犯？**
别装「去快捷方式箭头」类工具，尤其是替换 system dll、注入 shell 扩展的版本。只想去箭头的话，用一条 `Shell Icons` 指空白 ico 的方式就够了，且**不要动** `lnkfile` 和 `CLSID` 相关键。

## 注意事项

- **不需要管理员权限**（只改 `HKCU`），但改路径后需要重启资源管理器，任务栏会闪一下。
- 复制期间请先保存正在编辑的文件，避免个别文件被占用导致跳过。
- **不要**为了修图标去删 `Bags\1\Desktop` / `BagMRU`：会丢桌面图标坐标（作者踩过）。
- 本方法**不是万能灵药**：
  - 系统文件签名异常（`windows.storage.dll` / `shell32.dll` 不是 `Valid`）→ 先跑 `sfc /scannow` 和 `DISM /Online /Cleanup-Image /RestoreHealth`
  - 只有箭头没了、图标正常（症状 B）→ 不需要本脚本，删 `Shell Icons` 的 `29/77` 即可
  - 只有个别图标白纸（症状 D）→ 新版脚本会判 `可修(单)` / `可修(路径)` 自动处理；若判 `需人工`（商店应用 / 程序已卸载 / exe 本身没图标），重建快捷方式或手动指定 ico
- 工具的边界：商店应用（无目标路径）、程序已卸载且系统里找不到、exe 本身不含图标资源、同名程序有多个候选 —— 这四类只报原因不硬改，见[通用版](#通用版先自检能修的自动修推荐)。
- 脚本只动注册表、图标缓存、快捷方式和桌面路径，不碰任何用户文件内容。
- 三个 bat 文件为 **GBK(936) 编码**、CRLF 换行，用绝对路径调用 PowerShell，兼容 PATH 被裁剪的精简系统；三个 ps1 为 **UTF-8 with BOM**、CRLF，符合 PowerShell 5.1 的读取要求。
